# MVPロードマップ

目的：開業届を出す前に「売るもの」と「売る仕組み」の目処を、最小コストで検証する。

凡例：🧑 = 人間（判断・決裁・実物確認）／🤖 = エージェント／✅ = 着手済み

## 優先順位の考え方

1. **時間がかかる外部手続きは最初に着手**（Amazonの審査、APIの申請）。待ち時間に他の作業を並行する
2. **お金を使う前に判定基準を固定**。基準がないと、エージェントの提案を評価できない
3. **自動化は採算を確認してから投資**。MVPは「エージェントが調査・作成し、人が承認する」半自動で回す

## Phase 0：基盤づくり（1〜2週目／固定費：0円）

最小構成で始める。Amazonは**小口出品**（月額なし、1点売れるごとに100円）、Keepaは無料版を使う。

| # | 担当 | タスク | 理由 |
|---|---|---|---|
| 0-1 | 🧑 | Amazon出品者登録を申請（**小口**） | 審査に数日〜数週間かかるクリティカルパス |
| 0-2 | 🧑 | Keepaの無料のブラウザ拡張を導入 | 価格・ランキングの推移を目視で確認するため。有料版への切り替えは、手作業の確認がボトルネックになってから |
| 0-3 | 🧑 | 予算上限と撤退ラインを決め、`config/assumptions.toml` に記入 | 撤退判断を機械的に行うため |
| 0-4 | 🤖✅ | 判定基準（`docs/criteria.md`）と粗利計算ツール（`tools/profit_calc.py`）を用意 | 全エージェント共通の物差し |
| 0-5 | 🤖✅ | リサーチ・仕入れ評価エージェントを定義（`.claude/agents/`） | 最も価値が大きい「何を売るか」を先に自動化する |
| 0-6 | 🤖✅ | 出品クリエイティブエージェントを定義し、候補出しから決裁依頼までを1コマンド（`/sourcing-cycle`）にまとめる | 商品が決まり次第、すぐ出品原稿に入れる体制にする |
| 0-7 | 🤖✅ | 決裁の記録先（`data/decisions.md`）を用意 | 承認した内容と理由を残し、撤退判断の根拠にする |
| 0-8 | 🧑 | 出品方式を決める：既存ページへの相乗りか、新規ページの作成か | 新規作成にはJANコード（GS1 Japanへの登録が必要で有料）か、JANコード免除の申請が必要。出品エージェントの作業範囲もこれで変わる |

**前提：** 1回の仕入れは10個。粗利の試算から、売価は4,000円以上を狙う（`docs/criteria.md`）

### 小口出品で使えないもの（大口に切り替えるまで保留）

- SP-API（出品者向けの公式API）：販売運用と会計の自動化は、手作業（レポートのCSVをダウンロード → エージェントが集計）で代用する
- スポンサー広告：テスト販売は広告なしの自然検索だけになるため、売れるペースが遅めに出る点を割り引いて判断する

**大口へ切り替える条件：** 月の販売数が49点を超える（基本成約料100円 × 49点 ≒ 大口の月額4,900円）、または広告やAPIが必要になったとき

## Phase 1：商品検証（2〜5週目／費用：サンプル代として数万円）

| # | 担当 | タスク |
|---|---|---|
| 1-1 | 🤖 | 市場リサーチで候補を20品出す（公開情報で一次選別 → 🧑がKeepaの無料版で上位候補の推移を確認） |
| 1-2 | 🤖 | 仕入れ評価で20品を上位5品に絞る（粗利・規制・リスクで判定） |
| 1-3 | 🧑 | **【ゲート：決裁】** サンプル発注を承認する |
| 1-4 | 🧑 | 実物を検品し、実際のコスト（送料・関税・日数）を記録 → 🤖が再計算 |
| 1-5 | 🤖 | 出品クリエイティブエージェントを構築（1-3〜1-4と並行） |
| 1-6 | 🧑 | 商品の実物写真を撮影（メイン画像には実物写真が必須） |

**ゲートB：** 実際のコストで計算しても、判定基準を満たす商品が3品以上ある → Phase 2へ。満たさなければ1-1に戻る（最大2周で撤退を判断）

## Phase 2：テスト販売（5〜12週目）

| # | 担当 | タスク |
|---|---|---|
| 2-1 | 🤖 | 出品原稿を作成（タイトル、箇条書き、キーワード、画像の加工） |
| 2-2 | 🧑 | **【ゲート：公開承認】** 原稿を目視確認し、公開する |
| 2-3 | 🧑🤖 | 本発注 → FBA（Amazonの倉庫・配送代行）に納品 |
| 2-4 | 🤖 | 販売運用・会計エージェントを構築（セラーセントラルのレポートCSVを集計）し、粗利を週次でレポート |

**ゲートC：** 1か月で売り切れるペース、かつ実際の粗利率が基準以上 → **開業届と青色申告の承認申請**（開業から2か月以内に提出）→ 必要なら大口へ切り替え → 本格運用へ

## 後回しにするもの（MVPの範囲外）

- 楽天への出店（固定費と運用負荷が重い）
- 独自ブランド化・商標登録（売れる商品カテゴリが見えてから判断する）
- 仕入れ発注の完全自動化（7s goodにAPIがない場合、ブラウザ操作の自動化は壊れやすい）
